# SWE long-horizon agent cost dataset (`swe_log.jsonl.gz`)

Per-step LLM-call token and cost log for 3,000 long coding-agent runs. It is built from public trajectories and uses the same JSONL format as `research/sim/pilot_log.jsonl`. No API calls were made.

## Source
- Dataset: `nebius/SWE-rebench-openhands-trajectories`. URL: https://huggingface.co/datasets/nebius/SWE-rebench-openhands-trajectories
- Revision: commit `35455389ab51bf5e2306bfd436ef72d0f98bf882`, file `trajectories.parquet`, split `train`, 67,074 rows.
- License: CC-BY-4.0 (copy in `raw/LICENSE`). Cite Trofimova et al., "OpenHands Trajectories with Qwen3-Coder-480B-A35B-Instruct", Nebius blog, 2025.
- Generator: every trajectory comes from a single model, `Qwen/Qwen3-Coder-480B-A35B-Instruct`, running in OpenHands v0.54.0 with function calling. Issues come from nebius/SWE-rebench. The model is recorded as `src_model`.

## Sampling
- 3,000 row indices are drawn uniformly without replacement: `random.Random(0).sample(range(67074), 3000)`.
- Only the sampled rows are stored, in `raw/sample_3000_seed0.parquet` (the `model_patch` and gen-test columns are dropped). Runs are numbered `swe0..swe2999`, sorted by `trajectory_id`.
- Scripts are in `scripts/`:
  - `fetch.py`: streams the parquet file and keeps only the sampled rows.
  - `convert.py`: builds the JSONL log.
  - `stats.py`: prints the summary stats.

## Conversion rules
- Tokenizer: tiktoken `o200k_base` (`encode_ordinary`).
- Message tokens = tokens(content) + the sum of tokens(arguments string) over all tool calls. The function name is not counted.
- Each assistant message is one LLM call (step).
  - `prompt_tokens` is the sum, over every message before that turn (system, user, assistant, tool), of message tokens + 3.
  - `completion_tokens` is the message tokens of that assistant turn.
  - `est_prompt_tokens` = `prompt_tokens`.
- `kind` is `"final"` for the last assistant turn, or for any turn that calls the `finish` tool; in this sample those always coincide. Every other step is `"tool"`.
- `finish` is `"tool_calls"` if the turn has tool calls, otherwise `"stop"`.
- `cost` = prompt × $2.50/1M + completion × $10.00/1M, with no prompt caching. `model` is set to `"gpt-4o-priced"`.
- Run rows:
  - `finished` is `exit_status == "submit"`, which here equals "the last turn is a `finish` call".
  - `f1` is 1.0 if the dataset's `resolved == 1` (the issue's tests pass), otherwise 0.0.
  - Extra fields: `id` (trajectory_id), `instance_id`, `repo`, `exit_status_is_submit`, `last_turn_is_finish_call`.

## Caveats
- **Costs are counterfactual.** The token counts come from the trajectories, but the prices are gpt-4o list prices with no caching. The trajectories were generated by Qwen3-Coder, not by gpt-4o. Counts use the o200k tokenizer, not Qwen's tokenizer.
- **Tool schema not counted.** The OpenHands tool definitions (`raw/tools.json`, about 3.6k o200k tokens) are sent with every real call. They are not included in `prompt_tokens`, so prompt tokens are a lower bound (about 3.6k × steps per run).
- **No caching.** The context is re-billed in full on every step, so input tokens make up about 97% of cost. With prompt caching, real costs would be much lower.
- **Step limit.** OpenHands enforced a 100-step limit, so runs are truncated at 100 steps. The right tail of steps is bounded, but the per-run cost tail is not.
- **Run outcomes.** 9.2% of runs ended without a submit (step limit or an agent error). 18% of those still have `resolved = 1`, presumably from a partial patch.
